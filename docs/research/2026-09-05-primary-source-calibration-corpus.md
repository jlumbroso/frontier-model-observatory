# Frontier Model Observatory — Primary-Source Calibration Corpus Brief

**Retrieval date: 2026-09-05** (all HTTP metadata captured 2026-09-05 UTC from the sandbox; all page values come from pages fetched in this session). Providers covered: Anthropic, OpenAI, Google / Google DeepMind. Sources are provider-controlled surfaces only.

Two normalization conventions used below: values labeled **native** are quoted or paraphrased from provider text; values labeled **normalized** are this brief's interpretation (e.g. mapping "system card" and "model card" onto a common artifact class). HTTP header values (`last-modified`, `content-disposition`, redirect `location`) are transport-layer evidence, not provider editorial statements, and are labeled as such.

## 1. Executive synthesis

1. **All three providers now run an index surface, but the indexes disagree about what an "artifact" is.** Anthropic's [Model system cards index](https://www.anthropic.com/system-cards) is one row per release with a month-precision date; Google DeepMind's [Model cards index](https://deepmind.google/models/model-cards/) is one row per model with a "Published or updated date" that collapses first publication and revision into a single field; OpenAI's [Deployment Safety Hub](https://deploymentsafety.openai.com/) is a reverse-chronological post stream whose members include full system cards, addenda, "updates" to earlier cards, and one document the provider explicitly refuses to call a system card ([gpt-oss](https://deploymentsafety.openai.com/gpt-oss): "We're terming this document a model card, rather than a system card").
2. **Revision is first-class and heterogeneous.** Anthropic prints in-document changelogs with dated entries (e.g. [Claude Opus 4.6 System Card](https://www.anthropic.com/claude-opus-4-6-system-card) has four dated revision blocks: February 6, February 10, February 17, March 6, 2026). OpenAI attaches revision notes to the HTML card body (e.g. [GPT-Live](https://deploymentsafety.openai.com/gpt-live): "August 4, 2026" configuration-mismatch rerun; [GPT-5.2](https://deploymentsafety.openai.com/gpt-5-2): "This section was added on April 24, 2026"; [GPT-5.6 August Updates](https://deploymentsafety.openai.com/gpt-5-6-august-update): "August 19, 2026" score correction). Google prints paired dates inside the artifact ("Published: May 23, 2025, Updated: Jan 13, 2026" in [Veo 3 Model Card](https://storage.googleapis.com/deepmind-media/Model-Cards/Veo-3-Model-Card.pdf)) plus a standing boilerplate that cards "may be updated from time to time."
3. **URL identity and artifact identity are different things.** Anthropic serves recent cards from vanity paths that 307-redirect to hash-named PDF assets (`/claude-opus-5-system-card` → `/document/claude-opus-5-system-card` → PDF), and the same card is reachable through at least three official hosts (`anthropic.com`, `assets.anthropic.com` 301 → `www-cdn.anthropic.com`, plus `cdn.sanity.io` file URLs embedded in the pages). Google keeps `deepmind.google/models/model-cards/<slug>/` paths that 301 to `storage.googleapis.com` PDFs for PDF-era cards while serving HTML for post-Gemini-3.1 cards. OpenAI's o1 disclosure exists at three cdn URLs simultaneously, one of which carries a banner pointing at another.
4. **Modality coverage is asymmetric.** Google cards every officially released class (text/reasoning, image, video, music, audio/speech, robotics, open weights). OpenAI cards image ([ChatGPT Images 2.0](https://deploymentsafety.openai.com/chatgpt-images-2-0)), video ([Sora 2](https://deploymentsafety.openai.com/sora-2)), voice ([GPT-Live](https://deploymentsafety.openai.com/gpt-live)), agentic ([Operator](https://openai.com/index/operator-system-card/)), and open weights ([gpt-oss](https://openai.com/index/gpt-oss-model-card/)), but no card-class disclosure was found for embeddings or moderation endpoints. Anthropic's disclosures are text-first: its own [Model Report](https://www.anthropic.com/transparency/model-report) describes Claude modalities as text and image input with text output (plus text-to-speech on some models).
5. **Only Anthropic publishes actual system prompts.** [platform.claude.com/docs/en/release-notes/system-prompts/overview](https://platform.claude.com/docs/en/release-notes/system-prompts/overview) publishes dated prompt texts per model, with multiple dated entries per model before the 4.6 generation. OpenAI publishes a *behavioral specification* instead ([Model Spec](https://model-spec.openai.com/), snapshot-dated URLs), which is not a system prompt. No officially published Gemini app/consumer system prompt was found; this is a *not found*, not a confirmed absence.
6. **A 12-artifact minimum calibration set — four per provider — is enough, with three optional fifth artifacts** (see §8), because after those artifacts the remaining variation observed on these surfaces is combinatorial recurrence of already-covered dimensions, not new dimensions.

## 6. Cross-provider ontology findings

**Distinctions the schema must preserve**

1. **Artifact type as provider-native string, plus a normalized class.** Native types observed: "system card", "model card", "addendum", "Update to … System Card", "Model Report", "Model Spec", "technical report", "Risk Report", "Responsible Scaling Policy", "Constitution", "Terms of Use", "Evals & Methodology". OpenAI explicitly rejects one label for gpt-oss ("We're terming this document a model card, rather than a system card"), and Anthropic's own changelog records fixing "model card" → "system card" inside a document. Normalizing at ingest destroys real signal.
2. **Artifact vs artifact-version vs byte-object.** Three independent identifiers are needed: canonical/alias URL (`anthropic.com/claude-opus-5-system-card`, `deepmind.google/models/model-cards/gemini-3-pro/`), asset URL (hash PDF, `storage.googleapis.com` filename), and content hash/etag. Evidence: two live "Claude 4 System Card" assets; three live o1 PDFs; `assets.anthropic.com` 301 → `www-cdn.anthropic.com`.
3. **Four different date semantics.** (a) printed cover/publication date; (b) printed "Last Updated"/changelog dates; (c) index-surface "Published or updated date"; (d) transport `last-modified`. These disagree in practice: Gemini 3 Pro index "18 November 2025" vs document "Last Updated: May 2026"; Veo 3 document "Updated: Jan 13, 2026" vs `last-modified` 2026-03-26; Anthropic 2025-era cards all carry `last-modified` 2026-01-16.
4. **Subject cardinality and subject kind.** Subjects observed: single model (Claude Opus 4.6), two models in one document (Claude 4; Gemini Robotics 1.5 + ER 1.5; gpt-oss 120b/20b; GPT-Live-1 and mini), configurations of one model with different safeguards (Fable 5.1 / Mythos 5.1), checkpoint sets under one name (Gemini 2.5 Pro Experimental/Preview/GA), a mode (Gemini 2.5 Deep Think), a family (GPT-5.6 Sol/Terra/Luna), a product (Operator, ChatGPT agent), a deployment change (GPT-5 sensitive-conversations addendum: August 15 vs October 3 versions of the ChatGPT default model), and prospective scope ("covers Veo 3 and subsequent versions"; "covers Lyria 3.5 and subsequent versions").
5. **Document-part addressing.** Gemini 1.0, Gemini 1.5 and Gemini Robotics 1.5 cards exist only as sections of larger reports, addressed by page anchors. Records need part locators (section number, table number, page range) and a parent-document relation.
6. **Dependency and deferral relations.** Google cards routinely state "X is based on Y" and defer whole sections to the parent card (Gemini 3.5 Audio → Gemini 3 Pro; Gemini 3.8 Flash → Gemini 3.7 Flash; Veo 3.1 Lite → Veo 3; Gemini Robotics-ER 2 → Gemini 3.5 Flash). A card is therefore not self-contained: claim provenance must be able to point through the deferral chain.
7. **Document-relation types must be typed, not lumped.** Observed: *addendum to* (4o image generation → GPT-4o card; Claude 3.5 Sonnet addendum → Claude 3 Model Card), *update to* (GPT-5.2 → GPT-5 card), *addendum to an update* (GPT-5.2-Codex), *supersedes with pointer* (o1-preview reissue → December 5 card), *companion* (Anthropic Risk Report; Google Evals & Methodology; Google technical reports), *governing policy* (RSP versions, Preparedness Framework, Frontier Safety Framework, Model Spec, Constitution).
8. **Evaluation claims need their own bitemporal identity.** Providers republish numbers: GPT-Live's corrected illicit-behavior scores (0.97→0.95) with an original/corrected appendix; GPT-5.6's August 19, 2026 correction (0.4%→1.48%, pass@1 mistaken for pass@4); Claude Opus 4.6's BrowseComp revisions (83.97%→83.73%; 86.81%→86.57%); Claude Mythos Preview's revision of Claude Opus 4.6 CharXiv scores (61.5%→69.1%, 78.9%→84.7%) and USAMO 2026 (42.3%→66.2%). A benchmark value must be keyed by (model, benchmark, harness/config, artifact-version, asserted-at).
9. **Byte availability is a per-artifact property.** Anthropic: always a PDF. Google: PDF for older, HTML-only for newer. OpenAI: mixed within one surface — `gpt-5-5.pdf`, `gpt-6-astra.pdf`, `gpt-live.pdf`, `chatgpt-images-2-0.pdf` return 200 while `sora-2.pdf` and `gpt-oss/gpt-oss.pdf` 302 back to HTML.
10. **Prompt artifacts are a separate class with their own scope fields.** Anthropic prompt entries are scoped by model, date, surface (claude.ai vs API excluded) and input modality ("text only" vs "text and images"). The Model Spec, by contrast, is a normative spec versioned by snapshot URL. Conflating them would corrupt conversation-attribution work.

**False equivalences to avoid**

- "Model card" ≠ "system card" as provider intent, even when structurally similar (gpt-oss explicitly; Anthropic's pre-3.7 corpus uses "Model Card", post-3.7 "System Card").
- Index date ≠ publication date ≠ revision date ≠ HTTP `last-modified`.
- Alias URL ≠ artifact identity: `deepmind.google/models/model-cards/gemini-3-pro/` and `Gemini-3-Pro-Model-Card.pdf` are one artifact; `www-cdn…07b2a3f9.pdf` and `www-cdn…4263b940.pdf` are two versions of one artifact; the three o1 PDFs are three artifact-versions with one title.
- "Preview" and "GA" documents under one name are not duplicates (o1-preview vs o1; GPT-5.6 Preview vs GPT-5.6; Gemini 2.5 Pro Experimental/Preview/GA inside one card).
- A card's *stated* coverage is not its *effective* coverage: cards that defer sections to a parent card do not themselves document architecture or training data.
- Absence of a card ≠ absence of a release: the Google index footnote states "Gemini 2.0 Pro was released as an experimental model only", and OpenAI's ChatGPT Images 2.0 card references a "ChatGPT Images 1.5" deployment with no separate card found.
- Third-party mirrors (arXiv postings of OpenAI cards, Hugging Face copies, Scribd copies, aggregator "transparency hub" clones) are not provider artifacts and must never seed provenance records.

## 8. Recommended calibration set and stopping rule

**Recommended minimum set: 12 artifacts (4 per provider).** From §4, drop A3 or A5 only if a prompt class is out of scope; otherwise keep:

- **Anthropic:** A1 Claude Opus 4.6 System Card (dated in-document changelog; stable alias → PDF; provider self-corrected term), A2 Claude Fable 5.1 & Mythos 5.1 (two safeguard configurations; companion Risk Report), A3 Claude 4 System Card (two live byte-versions of one title; two models in one document), A5 Claude Opus 5 system prompts (prompt class, dated snapshot, non-API scope).
- **OpenAI:** O1 o1 trio (one title, three URLs, explicit cross-pointer, preview vs GA), O2 GPT-5.2 "Update to" (relation typing three levels deep; drifting comparison values), O3 GPT-Live (post-hoc numeric correction with original/corrected appendix; audio modality), O4 Sora 2 (HTML-only, no downloadable bytes, video+audio).  *Add O5 gpt-oss if the corpus will hold open-weight releases — it is the only artifact where the provider explicitly refuses the sibling term.*
- **Google:** G1 Gemini 3 Pro (alias→PDF, revision month in the title, index/document date conflict, declared dependent family), G3 Veo 3 (prospective "and subsequent versions" scope; documented dates plus an undocumented byte change; non-text modality), G4 Gemini Robotics 1.5 (card as an appendix table inside a report, two models), G5 Gemma 4 (open weights, platform-level timestamp only, separately versioned legal artifacts with an archive).  *G2 Gemini 2.5 Pro is the cheapest optional addition and is the cleanest single-card-many-checkpoints case.*

Coverage check against the required stresses: HTML vs PDF vs PDF-in-report (A1/G4/O4); one model vs family/system/product/deployment (A2, O2, G1, O4); updated-in-place vs new-version-new-URL (A1/G1/G3 vs A3/O1); text vs image/video/audio/robotics/open-weights (A1, O3, O4, G3, G4, G5); release-with-companions (A2 + Risk Report; G1 + evals methodology; G4 + release post and safety technical report); awkward/fragmented (O1's three URLs; A4's addendum-as-card if included; the `sora-2.pdf` 302).

**Stopping rule.** Stop adding artifacts when a candidate introduces no new value on the *documentary-variation vector*, defined as: {native artifact-type term; format (HTML / PDF / part-of-larger-document); byte availability (200 / redirect-to-HTML); URL topology (direct / alias-redirect / multi-host mirror / multiple live versions); date semantics present (cover, last-updated, in-document changelog, index-only, transport-only); subject cardinality (1 / n models, configurations, checkpoints, modes); subject kind (model / family / checkpoint / system / product / deployment); modality class; relation type to other artifacts (none / addendum / update / addendum-to-update / supersedes-with-pointer / companion / governing policy); scope temporality (retrospective vs "and subsequent versions"); claim-revision presence (numeric corrections republished)}.

Operationally: (1) encode each candidate as that vector; (2) accept it only if it adds an unseen value in at least one dimension, or an unseen *combination* that the ontology currently cannot express; (3) stop when three consecutive candidates from the same provider surface add nothing — which happened for every provider inside the sets above (e.g. Gemini 3.1 Pro, 3.5 Flash, 3.7 Flash, 3.8 Flash are the same vector as one another; Anthropic's Opus 4.7 / Sonnet 5 / Opus 4.8 repeat A1's vector; OpenAI's GPT-5.x hub cards repeat O2's); (4) re-open the set whenever ingest encounters a document that fails validation — the schema, not the corpus size, is the stopping criterion. Every "not found" in §7 (OpenAI/Google system prompts, embedding/moderation cards) must stay typed as *not found* rather than *absent*, and each should carry a scheduled re-check rather than a negative assertion.
